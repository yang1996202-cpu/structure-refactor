# Structure Refactor — 结构化重构器

把"有深度但散"的素材（文章草稿、读书笔记、会议纪要、调研资料）重构成**结论先行 + 金字塔骨架 + 论证对比**的成稿。

知识源：李忠秋《结构思考力》全书 98 条笔记（唯一锚点，不引入任何外部实战案例）。

## 核心理念

- 四个基本特点，朴素定义：**论=结论（先行）；证=证明（上下支撑）；类=分类（归类分组）；比=比较（对比定序）**
- 并不是"有主题分1、2、3点"就叫结构化——内在内容必须符合四个基本特点
- 散的根源 = 没有目标："没有目标的报告充其量只能被称为数据统计表"

## 它能做什么

输入一篇散素材，输出两部分：

1. **重构稿**：单线命题 + 六工位成文
2. **结构改动对照表**：原样 | 改后 | 对应书内哪个概念（每条可在笔记中溯源）

处理流程（六工位 + 一道质检）：

```
定目标(ABCD) → 三层标注(事实/理由/结论) → 定主题(简单/准确/利益)
→ 设计序言(SCQA) → 纵向搭骨架(疑问回答+概括聚合) → 横向选顺序(演绎/归纳)
→ 卖点包装
        ↓ 全程质检：论·证·类·比
```

## 两个核心深读（references/）

| 文件 | 内容 |
|---|---|
| `argument-comparison.md` | "论证对比"真身：证（演绎/归纳论证 + 可信度两问）× 比（时间/结构/重要性三种合法顺序），含书内原文锚点与常见误用边界 |
| `receiver-two-questions.md` | 接收两问的逻辑关系：**"所以呢"自下而上找结论（逼概括），"为什么呢"自上而下找理由（剥洋葱）**——方向相反，正好是第三章两种纵向方法的接收版 |

## 适合 / 不适合

**适合**：
- 公众号文章写到一半"太散了"，需要单线贯穿
- 消化别人的长文：防"被金句带走"，断言与结论分离
- 调研资料（网搜+聊天记录）整形为"一句话判断 + 支撑链"
- 周报自查：每条工作记录是否撑得住业绩结论（以上统下）

**不适合**：
- 从零创作（故事/剧本类用 save-the-cat 系）
- 纯排版美化（不碰格式）
- 商务 PPT 制作

## 知识源纪律

本 skill 的所有方法论规则**只锚定书内概念与原文**，不携带任何一次性的实战案例。实战材料只属于对话现场，不进 skill 规则——这是 v0.2.0 起的最高优先级约束。
